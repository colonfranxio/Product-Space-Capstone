# Track A implementation plan

**Goal:** Build sponsor navigation, viewing, and public pages against the existing backend.

**Architecture:** Server pages load RLS-scoped records; small client components handle creation, edit confirmation, and clipboard access. Gallery views use published snapshots. The editor opens `?preview=draft` after flushing its save. Both report routes consume Track B's `ReportRenderer`.

**Spec:** Main checkout `HANDOFF.md`, `design_handoff_sponsorstory/README.md`, and PRD section 11. Franxio confirmed the draft/live viewing distinction in chat.

**Constraints:** Work on `frontend/sponsors`, then `frontend/public-route`. Do not edit backend actions, migrations, contract, dependencies, or Track B files. Only Track A changes global CSS. Follow the existing dark admin design, 44px touch targets, keyboard focus, and responsive layouts.

## Tasks

- [ ] Add a tested Viewer loader: reject missing/mismatched records; default to frozen published content for every published sponsor; resolve saved draft only for drafts or explicit draft previews; never fall back to draft if a live snapshot is missing.
- [ ] Build sponsor grid and Viewer shell: empty state, published/draft/edit chips, logo/initials, separate card/pencil actions, published edit confirmation, creation errors, clipboard success/failure. Redirect event Create/Save to the returned event's gallery.
- [ ] Integrate B1's renderer once merged and add the public route on its own branch/PR. Missing/unpublished reports return notFound; no admin controls appear publicly.
- [ ] Run typecheck, lint, tests, build, and browser checks. Open the sponsors PR, then public-route PR in dependency order. After B2 is available, verify draft save/reload, live snapshot stability during edits, republish at the same URL, and remaining PRD scenarios.

## Review focus

- An owned sponsor under a different event URL must return notFound.
- Event branding edits must not change a published Viewer before republish.
- Draft preview URLs remain authenticated and have no public share controls.
- Failed creation and clipboard operations show errors, never false success.
- Published edits keep the Published chip alongside Unpublished edits; opening an editor does not mutate content.
